# Правила работы с этим репозиторием

Что такое проект и как устроен контент — в `README.md`. Здесь только то, что
легко нарушить по незнанию.

## Канон и сборка

Сайт целиком генерируется из канона. Генератор читает ровно четыре файла:

```
content/course.md      весь курс
content/письма.md      шесть писем
content/landing.html   шаблон лендинга
content/support.html   экран «сколько это стоит»
```

Пятый файл в `content/` — с испорченным именем
(`╨╛╨▒╤Л╤З╨╜╨░╤П-╨▓╨╡╤А╤Б╨╕╤П-╤Б╨╡╨▒╤П.md`, при коммите имя попало в
кодировку дважды; читается как «обычная-версия-себя»). Это старый черновик
курса, генератор его не читает, правки в нём ни на что не влияют.

**Сгенерированный HTML никогда не правится руками.** Это `index.html`,
`course/*.html`, `letters/*.html`, `support.html`. Тест сверяет каждую страницу
с выводом генератора, поэтому ручная правка роняет сборку. Нужно изменить
страницу — меняется канон, потом пересборка.

`site/` — замороженный прототип вёрстки, справочный материал. Не собирается и
не правится.

`scripts/build-site.ps1` закреплён в тесте по хешу sha256
(`tests/build-course-pages.test.mjs:44`). Любая правка генератора обязана идти
вместе с обновлением этого хеша — иначе тест красный. Меняй генератор только
осознанно.

## Локально (Windows)

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-site.ps1
node scripts/sync-quiz.mjs      # канон → assets/js/quiz.js
node --test                     # тесты
node scripts/verify-site.mjs    # политика статики и граф страниц
```

Пакетных зависимостей нет, `package.json` не нужен. Node 20+.

Посмотреть сайт в реальном оформлении: `node scripts/serve.mjs` (порт 8765).
Через `file://` относительные пути к CSS не резолвятся.

## В облачной сессии (Linux) и с телефона

Генератор — PowerShell, и тесты вызывают его именно как `powershell`
(`tests/build-course-pages.test.mjs:57`). Этого имени на Linux нет, поэтому в
облачной песочнице **нельзя** запустить ни `scripts/build-site.ps1`, ни
`node --test`. Не пытайся: это не чинится установкой pwsh, генератор закреплён
по хешу.

Что делать вместо этого:

1. Правь канон (`content/`), стили и скрипты (`assets/`), документацию.
2. Сгенерированный HTML не трогай вообще — он останется рассинхронизированным,
   и это нормально.
3. Коммить и открывай пул-реквест.
4. CI на `windows-latest` сам пересоберёт страницы, синхронизирует
   `assets/js/quiz.js`, допишет коммит «Пересборка страниц из канона» в ветку
   PR и прогонит тесты с верификатором.
5. Зелёный PR слить в `main` — развёртывание на Fly уедет само.

Проверить работу можно только по прогону CI. Не утверждай, что тесты проходят,
если ты их не запускал: в облачной сессии ты их запустить не мог.

Чем `node scripts/verify-site.mjs` и `node scripts/editorial-baseline.mjs`
полезны — они на чистом Node и работают в песочнице. Но `verify-site.mjs`
проверяет уже собранные страницы, так что после правки канона он говорит о
старом состоянии.

## Стиль

Документация, комментарии в `.ps1` и `.yml`, сообщения коммитов — по-русски.
В тестах на JS комментарии английские; в любом файле держись того языка,
который в нём уже есть.
