# ПРОМТ ДЛЯ CODEX: сборка сайта курса «Достаточная версия себя»

Ты — инженер, собирающий продакшн-версию сайта курса из готовых материалов этого репозитория. Контент и дизайн финализированы — твоя работа инженерная, не редакторская и не дизайнерская.

## 1. Контекст продукта (прочитай, это влияет на код)

«Достаточная версия себя» — курс-антитеза индустрии «лучшей версии себя». Ключевое продуктовое требование: **сайт обязан сам соблюдать то, чему учит курс.** Это не пожелание, а функциональные ограничения:

ЗАПРЕЩЕНО в любом виде: таймеры обратного отсчёта; счётчики «осталось N мест»; exit-intent-попапы; попапы подписки; уведомления-колокольчики; автоплей звука/видео; бесконечная прокрутка; геймификация чтения (стрики, ачивки, XP-очки за прогресс); тёмные паттерны согласий; сбор email до предоставления ценности; любые механики срочности и дефицита.

РАЗРЕШЕНО и желательно: тихий прогресс чтения; «продолжить с места»; шаринг по явному действию пользователя; ссылки «подумать и вернуться».

Тон микрокопирайта — сухая ирония (примеры в контенте: «кнопка никуда не денется», «дедлайна нет»). Не добавляй мотивационных фраз.

## 2. Исходники

- `content/обычная-версия-себя.md` — ЕДИНСТВЕННЫЙ источник контента. Структура: `#` = части (I/II/III/Неделя/Финал), `##` = модули и крупные разделы, `###` = разделы. Внутри: таблица (карта замен), 5 изображений `графики/*.png`, блоки практик (списки после строки «практика»/«Дополнение к практике недели»). Внутренние отсылки — по номерам модулей; НЕ переписывать текст.
- `content/письма.md` — шесть писем рассылки, готовые тексты.
- `design/DESIGN.md` + `variables.css`/`tokens.json` — дизайн-система SayBriefly («скетчбук на крем-бумаге»). Соблюдать буквально: канвас Cream Paper `#fcfaf5`; Forest Ink `#1a3300` — единственный хроматический авторитет (текст, CTA-заливка, бордеры); Highlighter Yellow `#ffe95c` — ТОЛЬКО маркер-выделение за словами/бейджи, никогда не CTA; Bricolage Grotesque 800 с tracking +0.04em — только дисплейные заголовки (никогда тело/UI/ниже 40px); Inter 400 тело 18px, 500–700 лейблы/подзаголовки; Roboto Mono — микролейблы; кнопки 6px (CTA: Forest Ink заливка + «→ » перед лейблом), карточки 12px, теги 9999px; иерархия бордерами 1px и цветными заливками, тени только subtle на кнопках; пастельные стикеры (Mint/Teal/Blush/Terracotta) — точечно, не по два в ряд.
- `site/index.html`, `site/курс.html` — рабочий прототип. Используй как референс поведения и вёрстки. В `index.html` есть **визард теста** («Мастер проверки автопилота», 8 вопросов + финальный вопрос об «обновлении до 2.0» + отчёт): перенести логику 1:1; стили — из общей дизайн-системы (жёлтая шапка-плашка, прогресс-«маркеры», опции-стикеры, кнопки ink/ghost). Стилевых исключений в проекте нет.

## 3. Целевой стек и структура

- **Astro** (static output) + TypeScript + ванильный CSS с токенами из `design/variables.css` (без Tailwind — токены уже есть). Node 20+.
- Контент через Astro Content Collections: на этапе сборки распарсить `обычная-версия-себя.md` и разрезать на страницы по `#`-частям (сплиттер написать в `scripts/split-content.ts`; исходный md не редактировать руками — он будет обновляться).
- Роуты (учти также «Неделю обычного человека» — она в md отдельным `#`-разделом и должна стать самостоятельной страницей `/week/` со ссылкой из финала и с лендинга):
  - `/` — лендинг (перенос index.html на компоненты)
  - `/course/` — оглавление курса (карта частей и разделов + «навигатор по боли» из введения md)
  - `/course/part-1|part-2|part-3|final/` — страницы частей; внутри — секции с якорями (слаги — транслит кириллицы, детерминированные)
  - `/test/` — визард отдельной страницей (на лендинге — секция-тизер со ссылкой)
  - `/week/` — «Неделя обычного человека»
  - `/glossary/` — «Словарь обычного человека»: собрать автоматически из терминов, размеченных в md жирным в первом вхождении (список терминов задать конфигом `data/glossary.ts`; первичный список: планка, прошивка, версия Pure, налог на радость, пожухший участок, зал ожидания, прайм-эра, быстрый/медленный контур, JOMO, карта замен, честная черта, pura vida)
- Компоненты: `PartLayout`, `SectionHeading` (h3 с жёлтым маркер-выделением), `PracticeBlock` (список практик в карточке-стикере), `ChartFigure` (img + подпись, чернильная рамка 12px), `SwapTable` (карта замен, мобильный скролл, mint-шапка), `TestWizard` (островной, vanilla JS или Preact-остров).

## 4. Функциональность

P0 (обязательно):
1. Полный перенос лендинга и курса на компоненты без потери контента; переходы лендинг→части→разделы (якоря из карточек программы ведут на соответствующие страницы/якоря).
2. Прогресс чтения: тонкая полоса сверху (Forest Ink) + сохранение позиции per-страница в localStorage; на `/course/` — отметка «читал/дочитал» по частям (тихо, без ачивок).
3. Визард теста: перенос 1:1, плюс кнопка «Поделиться результатом» — генерирует PNG-карточку через `<canvas>` в дизайн-системе (крем, чернильная рамка, «Обнаружено автопилотов: N из 8» с жёлтым маркером + вердикт) и вызывает Web Share API с фолбэком на скачивание. Никакой автопубликации.
4. Адаптив 360px+; таблица карты замен со скроллом; TOC на мобильных сворачивается в `<details>`.
5. Доступность: семантические заголовки, focus-visible (жёлтый outline), prefers-reduced-motion, aria на визарде, контраст AA (Forest Ink на Cream проходит с запасом; Pencil Gray — только для второстепенного).

P1:
6. `/glossary/` из конфига с обратными ссылками «где встречается» (по якорям секций).
7. Печать: `@media print` для страниц частей (чёрный текст, без TOC/прогресса, графики на всю ширину) — это замена PDF на первом этапе.
8. OG-мета и превью-картинки на каждую часть (генерация на этапе сборки: заголовок части на Cream, жёлтый маркер под ключевым словом, Bricolage Grotesque).

P2 (если останется время):
9. Поиск по курсу (pagefind).
10. Страница `/letters/` — шесть писем из `content/письма.md` (уже написаны): список + страницы писем, вёрстка как у частей.

## 5. Критерии приёмки

- `npm run build` собирает статику без ошибок; Lighthouse (mobile): Performance ≥ 95, A11y ≥ 95; JS-бандл вне страницы теста ≤ 15 КБ gzip.
- Грепом по собранному сайту не находится ни одного: `setTimeout.*осталось`, `countdown`, `только сегодня`, `спеши`, `popup`.
- Визуальная сверка с `site/index.html`: та же композиция секций (hero → словарь → программа → совместимость → условия → тест → CTA); CTA — Forest Ink/6px со стрелкой «→»; часть I — mint-стикер; второй term-стикер — teal; зачёркивания терракотовые; исправления и takeaway — жёлтым маркером.
- Визард теста проходит все 9 шагов с клавиатуры; результат шарится картинкой; стили визарда используют только токены системы.
- Все 5 графиков на местах, alt-тексты из подписей md.
- Исходный `content/обычная-версия-себя.md` не изменён (diff пустой).

## 6. Порядок работы

1) Прочитай README.md, DESIGN.md и пролистай контент-md (заголовки), 2) подними Astro-скелет с токенами, 3) напиши и протестируй сплиттер контента (snapshot-тест: количество секций и якорей стабильно), 4) лендинг, 5) страницы частей, 6) визард теста+шаринг, 7) прогресс/глоссарий/печать, 8) прогони критерии приёмки и приложи отчёт в `ACCEPTANCE.md`.

Вопросы формулируй пакетно после этапа 1, если что-то в исходниках противоречит этому ТЗ — ТЗ приоритетнее прототипа, контент-md приоритетнее всего.
